== Containers

Edigen is a small single-process CLI application, so its "containers" are the
executable itself, the resources it bundles, and the files it reads and writes.
The container diagram makes the data flow explicit: a specification file in, one
Java decoder source file out, using templates embedded in the JAR.

=== Containers and stores

[cols="1,1,3",options="header"]
|===
| Element | Type | Responsibility

| Edigen CLI Application | Container (executable JAR, Java 11)
| The entire compiler. Parses command-line arguments, drives the parse ->
  transform -> generate pipeline, and writes the output files. Entry point:
  `net.emustudio.edigen.Edigen`.

| Bundled Template | Container (classpath resource)
| `src/main/resources/Decoder.edt` provides the shared Java
  runtime scaffold around the generated code fragments. Loaded from the JAR unless
  decoder template overridden with `-dt`.

| Specification (`.eds`) | Data store (input file)
| The DSL description of the instruction set: decoder rules and disassembler
  formats separated by `%%`.

| Generated Decoder | Data store (output file)
| `Decoder.java`, written to the configured output directory (`-do`).
|===

=== Command-line contract

The application is configured entirely through the arguments parsed by the
`ui.CommandLine` component. The mandatory arguments and the most relevant options
are:

[cols="1,1,3",options="header"]
|===
| Argument | Setting | Meaning

| `<specification>` | `SPECIFICATION` | Path to the input `.eds` file.
| `<decoder>` | `DECODER_NAME` | Fully-qualified name of the generated decoder class.
| `-do <dir>` | `DECODER_DIRECTORY` | Output directory for the decoder.
| `-dt <file>` | `DECODER_TEMPLATE` | Custom decoder template (overrides the bundled one).
| `-iu` | `IGNORE_UNUSED_RULES` | Skip the unused-rule check.
| `-d` | `DEBUG` | Dump the AST after each transformation pass.
|===
