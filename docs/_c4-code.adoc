== Code

The code level zooms into the two most important internal structures: the *AST node
model* that every component shares, and the *transformation pipeline* that turns a
parsed tree into a decision tree ready for emission.

=== AST node model

All nodes extend `TreeNode`. `Specification` is the root and holds exactly one
`Decoder` and one `Disassembler` subtree. The decoder side is expressed with rules,
variants, masks and patterns; the disassembler side with formats and values.

[cols="1,3",options="header"]
|===
| Node | Role

| `Specification` | Root; always contains one `Decoder` and one `Disassembler` subtree.
| `Rule` | A decoder rule, possibly with multiple names.
| `Variant` | One branch of a rule; commits to a decoded value/string on match.
| `Subrule` | A reference to another rule, or a value-capturing field.
| `Pattern` | A sequence of bits to match during decoding.
| `Mask` | A bit mask used to filter bits during pattern matching.
| `Format` | One disassembler output format string.
| `Value` | One disassembler parameter, bound to a decoder rule name.
|===

=== Transformation pipeline

`Translator.transform(...)` runs the following visitors in a fixed order. Early
passes resolve meaning and validate intent; middle passes normalize variants into
bit-test nodes; later passes compact the tree and remove invalid or useless
branches. When `IGNORE_UNUSED_RULES` is set, step 3 is replaced by a no-op visitor.

[plantuml,c4-code-pipeline,svg]
....
@startuml
skinparam shadowing false
skinparam ArrowColor #4A4A4A
skinparam activityBorderColor #2E4E7E
skinparam activityBackgroundColor #E8F0FE

start
:ResolveNamesVisitor;
:DetectRootRulesVisitor;
:DetectUnusedRulesVisitor;
:SemanticCheckVisitor;
:MergePatternsVisitor;
:SortVisitor;
:SplitVisitor;
:PushDownVariantsVisitor;
:GroupVisitor;
:DetectAmbiguousVisitor;
:NarrowMasksVisitor;
:RemoveUnreachablePatternsVisitor;
:DetectUnreachableFormatsVisitor;
stop
@enduml
....

[cols="1,2,4",options="header"]
|===
| # | Pass | Purpose

| 1 | `ResolveNamesVisitor`
| Resolve subrule references to rules, resolve returned subrules, and synthesize
  implicit rules for typed subrules with no explicit definition.

| 2 | `DetectRootRulesVisitor`
| Bind declared root-rule names to `Rule` objects, preserve declaration order, and
  reject undefined or duplicated roots.

| 3 | `DetectUnusedRulesVisitor`
| Reachability analysis from the roots; unreachable rules are errors unless `-iu`
  is set.

| 4 | `SemanticCheckVisitor`
| Validate remaining semantics: unbounded subrule only at a variant end, no
  duplicated disassembler value sets, every disassembler value must come from a
  returning rule.

| 5 | `MergePatternsVisitor`
| First major rewrite: concatenate each variant's constants into one `Mask` + one
  `Pattern` and compute subrule bit offsets.

| 6 | `SortVisitor`
| Order variants by mask length so decoding never reads beyond the current
  instruction.

| 7 | `SplitVisitor`
| Split masks/patterns longer than the decoder unit size (32 bits) into a vertical
  chain, enabling long / variable-length instructions.

| 8 | `PushDownVariantsVisitor`
| Push variants to the leaves so the tree becomes a real decision tree: internal
  nodes test bits, leaves commit to a variant.

| 9 | `GroupVisitor`
| Merge sibling masks/patterns with identical bit sequences so shared prefixes
  collapse into common decision nodes.

| 10 | `DetectAmbiguousVisitor`
| On the grouped tree, detect variant and path ambiguity (non-mutating check).

| 11 | `NarrowMasksVisitor`
| Keep one child mask on the main path; move the rest under a synthetic empty
  `Pattern` that models the "try next mask" default branch.

| 12 | `RemoveUnreachablePatternsVisitor`
| Drop pattern layers under zero-only masks (their comparison is always true).

| 13 | `DetectUnreachableFormatsVisitor`
| Compute reachable decoder-key sets and compare with disassembler value sets;
  report unreachable formats as errors and missing formats as information.
|===

.Resulting decoder subtree shape
[source,text]
----
Decoder
  Rule
    Mask
      Pattern
        Mask
          Pattern
            Variant
----

This is exactly the shape `GenerateMethodsVisitor` expects, which is why the
generators themselves stay small.

=== Generation and templating

The generators map the normalized tree onto Java control flow:

[cols="1,3",options="header"]
|===
| AST node | Generated Java (decoder)

| `Rule` | a private method
| `Mask` | a `readBits(...)` call plus a `switch`
| `Pattern` | a `case ...:` or `default:` label
| `Variant` | an `instruction.add(...)` statement
| `Subrule` | a recursive call into another generated rule method
|===

`DecoderGenerator` fills `%decoder_package%`, `%decoder_class%`, `%root_rule%`,
`%decoder_fields%` and `%decoder_methods%`; `DisassemblerGenerator` fills
`%disasm_package%`, `%disasm_class%`, `%decoder_name%`, `%disasm_formats%` and
`%disasm_parameters%`. `Template` substitutes these variables into the `.edt`
templates, and `PrettyPrinter` supplies indentation, producing the final Java
source files.
